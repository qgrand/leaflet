## What

Three steps: target → archetype → studio. Studio is two-column: a form generated from the archetype's field definitions on the left, live preview on the right, then format selection (`md`/`docx`/`pdf`/`html`) and Generate. **Field type vocabulary to support:** `text`, `textarea`, `select` (+`options`), `list`, `reasoned-list`, `table-list` (+`keys`), plus optional `section` for collapsible fieldsets and an archetype-level `layout` hint. **Validation errors must be returned per-field, not as one opaque failure** — iSconl's `validate()` returns an error array and the UI should bind each to its control. **This is the "editor" being mirrored** — not a rich-text editor. Qpress has both: Tiptap for Mode 1 freeform posts, this wizard for Mode 2 structured documents.

## Notes

**Scoped 12 Sep 2026.** The iSconl wizard is proven in real use; copy its flow rather than redesigning. Deliberately NOT porting: its `localStorage`-only autosave (Qpress should persist drafts server-side) and its always-empty recency ordering. **FOLDED IN 15 Sep 2026, PLAN session (`relay-29`), from `BP26091301`, which existed only to carry this into here and is now closed.** **The live preview must be structurally identical to the print/PDF output, not a separate approximation — this is Sconl's explicit requirement and it is now this row's standing rule, not a nice-to-have.** **The layout pattern is already verified, so do not re-derive it:** margins come from `@page { size: A4; margin: <mm> }` and never from the page container's own padding; the container is a plain block with `min-height` only — **no fixed height, no `aspect-ratio`, no `overflow-y`**; `break-inside: avoid` on table rows and list items. **Two traps that cost a real session to find, both of which silently LOSE content rather than merely misplacing it:** (1) a `display:flex; flex-direction:column` page container makes Chromium's print engine drop content outright when the container spans a page break — never lay out a print target as a paginating flex container; (2) the `aspect-ratio:210/297` + `overflow-y:auto` approach that *simulates* a page on screen is worse than wrong for print, because a print engine does not paginate a scrolling container, it clips it to the fixed box height, so everything past the fold vanishes from the PDF instead of flowing to page 2. **Why `min-height` is the right primitive and not just the safe one:** it makes an on-screen overflow an honest signal that the PDF will also spill to a second page, which is exactly what WYSIWYG means here. **Reference implementation, already fixed in place and verified:** `work/dev/Systems/iSconl/scope/docs/examples/weekly-status-brief.reference.html` — confirmed via headless Chrome plus `pdfinfo`, with both the broken two-page/content-loss state and the fixed single-page state reproduced. Read it before writing the renderer.
