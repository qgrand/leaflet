> found 17 Sep 2026, BUILD session, while building the Creator Studio wizard

## What

`archetype.rs`'s `ValidationResult` is `{ valid: bool, errors: Vec<String> }`,
and every archetype builds those strings as
`format!("missing required field: {f}")`. There is nowhere to put the
field name as data.

`BB26091204` requires validation errors to bind to their own control
rather than surfacing as one opaque failure, so the wizard currently
recovers the field by regex over that sentence
(`normalizeErrors()` in `app/web/lib/archetypes.ts`). It works, and it
keeps an error it cannot attribute rather than dropping it — but the
binding breaks silently the day anyone rewords an error message, which
is the sort of change nobody expects to be load-bearing.

Change `errors` to carry a field name alongside the message (a small
struct, or a `(field, message)` pair), have the archetypes emit it, and
have the schema/preview/generate endpoints return `errors: [{field,
message}]`. The wizard already reads that shape.

## Notes

The wizard's string parsing should stay after this lands, as a fallback
— it costs nothing and means an error from an older engine build still
reaches the right control.

Blocked in practice by the same thing as everything else in `app/api`:
no Rust compiles on this machine (`BH26091501`).
