## What

**A shell on the VM.** A session reached the VM read-only and produced the full survey, but every remote WRITE was refused by the permission classifier (`Remote Shell Writes`). The script is written, idempotent, and prints no credential values.

## Exact steps

**The script is at `_recovery/scope-prerewrite-20260912/vm-remediate.sh`** (copied out of the session scratchpad). Run: `scp -i <key> vm-remediate.sh ubuntu@140.238.100.0:/tmp/ && ssh -i <key> ubuntu@140.238.100.0 'bash /tmp/vm-remediate.sh'`. Key comes from Bitwarden `ISCONL_VM_SSH_PRIVATE_KEY` (needs a trailing newline to parse). **What it does, in order:** (1) strips the embedded `x-access-token:<PAT>@` from every remote URL — 7 of 9 checkouts have one: `circle`, `hub`, `media`, `pulse`, `scope`, `spark`, `vault`; `ops` and `qspace-press` are already clean. All repos are public and the deploy only fetches, so token-free HTTPS keeps working. (2) Re-clones `scope` — it **refuses if the checkout is dirty** rather than destroying anything, and moves the old clone aside to `scope.pre-scrub-<stamp>` instead of deleting it. (3) Verifies the scrub on the fresh clone. (4) Appends 4 `SCOPE_*` vars to `deploy/.env`, backing it up first and skipping any key already present. (5) Discards the now-committed `qspace-press` Dockerfile edit. (6) Final credential sweep.

## Notes

**Why the re-clone and not a reset:** `git fetch` + `reset --hard` recovers the *checkout* but does **not** remove objects. The VM's `scope` clone still holds **3 commits touching the deleted tenant archetype and 18 reflog entries** — readable by anyone with shell access. Only a genuine re-clone (or an aggressive reflog-expire + gc) removes them. A reset would look like it worked. **Why the env vars matter:** `staging` now carries code where four tenant paths read from the environment with no default. That is deliberate and safe — features no-op rather than writing to a wrong folder — but OneDrive document push, the binder, and deliverable collection stay inert until these are set. **Delete `scope.pre-scrub-<stamp>` only after verifying the fresh clone works.**
