## What

Creator Studio autosaves a draft to the account rather than the browser
— `BB26091204` excludes iSconl's `localStorage` autosave from what gets
copied across, because a draft in a browser is lost the moment the
creator changes machine. The wizard therefore already writes to
`GET /api/drafts?key=` and `PUT /api/drafts`, which proxy to
`GET /documents/drafts/:key` and `PUT /documents/drafts` on the engine.

Those two engine endpoints do not exist. Build them: a table keyed by
creator + target + archetype, holding the raw form values and a
timestamp, with last-write-wins and no versioning (a draft is not a
document; the document registry is `BB26091208`'s job).

The wizard degrades quietly today — a failed draft read starts a clean
form, a failed write just leaves the "Draft saved" line blank — so this
is a missing feature rather than a break.

## What the wizard already sends

```
PUT /documents/drafts
{ key, archetypeId, namespace, values: {fieldName: rawText}, savedAt }

GET /documents/drafts/:key  ->  the same object, or 404
```

`key` is `${targetKind}:${targetId || "_"}:${archetypeId}`.
