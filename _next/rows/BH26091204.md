## Status note (from the legacy row)

## What

**Your GitHub account.** A classic PAT cannot be minted from the CLI; it needs the web UI.

## Exact steps

GitHub → Settings → Developer settings → Personal access tokens → revoke the current `isconl` token and issue a replacement. **Then decide whether anything still needs it at all:** after `BH26091203`, no VM remote embeds a credential, and the deploy only *fetches* public repos, so a token may not be required on that host any more. If something does need one, prefer an SSH deploy key or a credential helper over re-embedding a token in a URL — see canon D-016. Also update Bitwarden `ISCONL_GITHUB_TOKEN`.

## Notes

**This is the most urgent item on the board.** The token is live, carries push rights to `isconl/*`, and sat in plaintext on a host whose repos are all public. **It leaked twice through `git remote -v` — 5 Sep and 12 Sep, seven days apart — and `KI26090604` was opened for the first one and never actioned.** Two transcripts now contain it. Rotation is the only thing that makes those transcripts harmless; everything else is mitigation. Sequence this **after** `BH26091203` so the VM is not re-pointed twice.
