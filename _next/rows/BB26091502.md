## What

**Sconl's original ask: change the publish-artifact button to "Canvas", a live editable HTML artifact, and use it to share course modules with his Viva team.** **Build the surface, not a course feature.** **(1) Rename the existing "Publish artifact" action to Canvas** in Qpress's Creator Studio. **(2) Make Canvas a live-editable HTML artifact** — the published thing stays editable rather than being a frozen render, which is the whole point of the name. **(3) Build it content-type agnostic.** Canvas takes rendered HTML and a title and publishes an editable, shareable artifact. **It must not know what a course module is.** **(4) Sharing reuses the existing unauthenticated share mechanism** — the `/api/public/learn/:course/:slug` pattern `BL26091102` already built for standalone module export is the working precedent for public, no-login sharing; Canvas becomes the editable front end over that same idea. **Why generic and not a course content type — this is the scoping call and it follows directly from Sconl's decision:** on 15 Sep he ruled that **iSpark stays its own product** and is not folded into Qpress. Course content therefore belongs to iSpark. **Adding a "course" content type to Qpress's post model would quietly re-implement the fold he just ruled out.** A generic Canvas serves the original purpose without that: iSpark reuses Qpress's rendering engine (already his stated direction) and publishes course modules through Canvas the same way anything else does. **Sequence after `BB26091204`** (Creator Studio wizard and live preview) — Canvas is an action inside that surface and there is nowhere to put it before it exists. **Read `BB26091204`'s folded-in print-template rules before building**, since a Canvas artifact is the same HTML that has to survive print.
