> found 17 Sep 2026, BUILD session, while verifying `BB26091204`

## What

`pnpm build` in `app/web` compiles cleanly and generates every page, then
fails at the very last step:

```
✓ Compiled successfully
✓ Generating static pages (18/18)
Collecting build traces ...
Error: EPERM: operation not permitted, symlink
  '...\node_modules\.pnpm\@next+env@14.2.15\node_modules\@next\env'
  -> '...\app\web\.next\standalone\...'
```

`next.config.mjs` sets `output: "standalone"`, and Next builds that
directory by symlinking every traced dependency out of pnpm's store.
Creating a symlink on Windows needs either an elevated shell or
**Settings → System → For developers → Developer Mode: On**. Turning
Developer Mode on is the fix, and it is a one-time machine setting only
Sconl can change.

## Why it matters, and why it is not urgent

Nothing about the app is broken: the compile, the type check, the lint
and all 18 pages succeed, and `next dev` runs normally — this session
drove the whole Creator Studio wizard against it. CI and the OCI VM build
on Linux, where symlinks are unrestricted, so **deploys are unaffected.**

What it costs is local verification: a session on this machine cannot get
a green `pnpm build` and so cannot honestly say the production build
passes end to end, only that it compiles and renders. That is the same
shape of gap as `BH26091501` on the Rust side, just much smaller and with
a much simpler fix.

## The ask

Turn on Developer Mode (Settings → System → For developers), or say you
would rather not and this row gets closed as "won't fix, Linux CI covers
it" — both are reasonable, and nothing is waiting on the answer.
